新语言 shya（设计稿 v2）
本文档是设计稿的修订版；与 v1（docs/design-draft-v1.txt）的差异逐条记录在 docs/design-v2.md
本 dsl 为强类型语言，类型标注和 ts 规则一致，但只有基本的类型系统，无法自定义类，但可以通过 declare 声明外置对象以对接游戏系统
本语言最终编译为 js 运行，编译目标为 es2026
编译步骤：
词法分析 → 语法分析（AST）→ 模块加载（.shya 宏文件）→ 宏展开/脱糖 → 核心 AST → 类型检查 → 代码生成
设计理念：
用最接近自然语言的语法写规则逻辑，用宏做模板与复用，用宿主桥拿底层能力，最终编译成 JS 跑在任何地方。

外置对象声明：
declare Player {
  name: string            字段：编译成属性读取 p.name
  hp: number
  hand: array<Card>
  judge(): Card           方法：编译成调用 p.judge()
  recover(n: number): void
  draw(n: number = 1): void
  note?: string           可选字段
}
declare fn hostRandom(max: number): number
declare 只参与类型检查，不产出任何 JavaScript
字段读属性、方法发调用；访问未声明成员报 TC014 警告
declare 里写的默认值只描述宿主契约，不会注入到调用点

语句：
赋值：

可变为let，
不可变为const（被重新赋值时必须是 let）

player draw(a+a) ->player draw(100+100)

自增：
i++

循环：
只有for(condition)循环
只有for of遍历

系统宏：
将后面部分直接按ts语法解析：
@ts {}只能嵌套@ts
@ts 里的 #插槽 会被替换成实参节点
@when(){
#y:
#n:
}分支编译
只填第一个的话，可不具名：
@when(){}
判定顺序：插槽形态 → 值类型 → AST 节点种类
判定是三值的，unknown 不会命中任何分支；一个都不匹配报 MAC020
@each(#slot of #slots){}
x/_ @range start:end,step
标准库宏：
a @keys -> Object.keys(a)
macro @keys(#x){
@ts{Object.keys(#x)}
}
b @values-> Object.values(b)
c @entries -> Object.entries(c)
array @len -> array.length
string @len -> string.length
map @len -> map.size
set @len -> set.size
macro @len(#x){
@when(#x is array || #x is string)@ts{#x.length}
@when(#x is map || #x is set) @ts{#x.size}
}
你能像操作数组一样操作所有迭代器，最终仍为原始类型
d @safe say("hello") say("nice")
js编译产物->
d?.say("hello")?.say("nice")
macro @safe(#x,...#slots:callExpr){
#x @each(#slot of #slots){
@when(#slot is safeCallExpr){
y:#slot
n:?#slot
}
}
}
player nextSeat @share _p recover(2) draw(2)
js编译产物->
const _p = player.nextSeat()
_p.recover(2)
_p.draw(2)
macro @share(#x,#y,...#slots:callExpr){
#y = #x
@each(#slot of #slots){
#y #slot
}
}
player nextSeat @safe_share _p recover(2) draw(2)
->
const _p = player.nextSeat()
_p?.recover(2)
_p?.draw(2)
macro @safe_share(#x,#y,...#slots:callExpr){
#y = #x
@each(#slot of #slots){
#y @when(#slot is safeCallExpr){y:#slot,n:?#slot}
}
}

大部分安全的 AST 节点种类都可以直接作为插槽类型：

导入：
普通模块（.js/.mjs）规则与ts一致，原样透传
宏文件（.shya）走同一套 import 语法，编译期加载，不产出 JavaScript：
import "./pystd.shya"                            导入该文件全部宏
import { @enumerate, @zip } from "./pystd.shya"  只导入这几个
具名导入会自动带上被依赖的宏（依赖闭包）
被导入文件里的 define 与 declare 一并进入导入方
路径以 ./ ../ 开头时相对当前源文件；否则在 -I 指定的搜索根下查找
循环导入报 MOD002；宏文件里导入非 .shya 报 MOD004
未做说明的和js保持一致
