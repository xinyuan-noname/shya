feat(macro): optional slots, expression-position slot values, case-sensitive node kinds

Slot types are now the AST node kind names themselves (`Ident`, `Str`,
`ObjectLit`, `Compare`, `Block`, `If` …), matched case-sensitively, with a
MAC015 that names the right spelling for a legacy one (`strLit` -> `Str`,
`objectLit` -> `ObjectLit`). The base categories (`expr`/`stmt`/`type`/
`expr[]`, `callExpr`/`safeCallExpr`) and the @when decision order are
unchanged.

`#name: Type?` marks a slot optional: an omitted one binds to nothing, a whole
statement that only used it is dropped, and where a value is unavoidable it
becomes `undefined` instead of leaving a syntax hole. Named-slot values
(`#name: value`, which the parser stores as a statement Block) now contribute
their expression in expression position instead of being cloned verbatim -
`{ translation: { ""; } }` was the old, broken output.

- macro: `astKindTable()` renamed, `astKindAliasTable()` + case check for the
  legacy-spelling diagnostic, `optional` per parameter, `instBlockExpr()` for
  block values, `SlotRef` expands recursively with a self-reference guard,
  empty assignments/statements vanish, `Codegen` prints `{}` and `undefined`
  where a hole used to be
- tests: 17/17 cases including the new 16-type-name-case and 17-optional-slots;
  goldens for 02-macros and 11-ast-types follow the cleaner output
- docs: language reference, AST node table, decision records H1-H3, examples
- vscode-shya 0.2.3: slot-type completion in a macro header, AST kind
  highlighting, legacy spellings suggested with their replacement
- build-wasm.bat: ASCII comments (its Chinese ones had been mangled to `??`)
